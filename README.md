# University Attendance System

A Flutter + Firebase (Auth + Firestore) app with role-based routing for
teachers and students, checkbox-based attendance submission, and real-time
attendance status for students.

## Project structure

```
lib/
  models/           UserModel, CourseModel, AttendanceRecordModel
  services/         AuthService (Firebase Auth), FirestoreService (Firestore)
  screens/
    auth/            LoginScreen, AuthGate (role-based redirect)
    teacher/         TeacherDashboardScreen, AttendanceRosterScreen
    student/         StudentDashboardScreen (real-time status badges)
  main.dart
  firebase_options.dart   placeholder — regenerated by flutterfire configure
firestore.rules      role-aware security rules for users/courses/attendance
```

## Prerequisites

- Flutter SDK (3.x or later) — https://docs.flutter.dev/get-started/install
- A Firebase project with **Authentication (Email/Password)** and
  **Cloud Firestore** enabled — https://console.firebase.google.com
- Node.js (for the Firebase CLI) and the FlutterFire CLI

## 1. Install the Flutter SDK and verify it

```bash
flutter --version
flutter doctor
```

Resolve anything `flutter doctor` flags (Android SDK, Xcode, etc.) before continuing.

## 2. Get project dependencies

From the project root (where `pubspec.yaml` lives):

```bash
flutter pub get
```

## 3. Install the Firebase CLI and FlutterFire CLI

```bash
npm install -g firebase-tools
firebase login

dart pub global activate flutterfire_cli
```

## 4. Connect the app to your Firebase project

This generates the real `lib/firebase_options.dart`, replacing the
placeholder included in this zip:

```bash
flutterfire configure
```

Follow the prompts to select (or create) your Firebase project and the
platforms you want to build for (Android/iOS/web/etc.).

## 5. Enable Auth + Firestore in the Firebase Console

- Authentication → Sign-in method → enable **Email/Password**
- Firestore Database → Create database (start in production mode)

## 6. Deploy the security rules

```bash
firebase init firestore   # first time only, point it at this project
firebase deploy --only firestore:rules
```

(`firestore.rules` in this project already contains role-aware rules for
`users`, `courses`, and `attendance` — see the file for details.)

## 7. Seed some data (manual, for testing)

In the Firestore console, create:

- `users/{uid}` → `{ name, email, role: "teacher" | "student" }` for each
  test account (uid must match the Firebase Auth user's UID)
- `courses/{courseId}` → `{ courseName, teacherId, studentIds: [...] }`

## 8. Run the app

List available devices/emulators:

```bash
flutter devices
```

Run on a connected device or emulator:

```bash
flutter run
```

Run on a specific platform:

```bash
flutter run -d chrome     # web
flutter run -d macos      # macOS desktop
flutter run -d android    # Android device/emulator
flutter run -d ios        # iOS simulator (macOS only)
```

## 9. Build a release version (optional)

```bash
flutter build apk --release        # Android APK
flutter build appbundle --release  # Android App Bundle (Play Store)
flutter build ios --release        # iOS (macOS only, needs Xcode signing)
flutter build web --release        # Web
```

## 10. Run tests / analyzer (optional)

```bash
flutter analyze
flutter test
```

## Notes

- `lib/firebase_options.dart` in this zip is a **placeholder** that throws
  on purpose — you must run `flutterfire configure` (step 4) before the
  app will actually connect to Firebase.
- The roster screen currently shows student UIDs; wire it up to the
  `users` collection to show names once you've seeded real accounts.
- Attendance report/PDF export (via the `pdf` + `printing` packages) is
  a separate module — ask if you'd like that scaffolded too.
